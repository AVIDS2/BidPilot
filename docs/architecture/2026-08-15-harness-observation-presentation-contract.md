# Harness Observation 与用户呈现契约

日期：2026-08-15
状态：已实现的运行时边界，后续功能必须遵守。

## 目标

BidPilot 的执行助手不是把工具调用日志翻译给用户的聊天框。它必须同时满足两件看似矛盾的事：

1. 模型在下一轮能够看到足够的工具 observation、稳定失败码和暂停原因，进而决定继续、改用工具、等待或向用户补问；
2. 普通用户不会看到内部推理、原始参数、运行 ID、供应商协议包、异常堆栈或未经审查的外部内容。

## 三个通道

```text
工具/业务服务
  ├─ model_payload  -> 下一轮模型上下文（深度脱敏、受长度限制）
  ├─ public_payload -> 用户活动时间线（安全摘要、来源、结果入口）
  └─ audit payload  -> PostgreSQL 审计与受权诊断（不进入常规聊天）
```

`HarnessToolOutcome` 显式区分 `model_payload` 与 `public_payload`。核心循环把前者写入 `role=tool` 的下一轮模型消息，把后者发为可持久化事件。任何新增工具不得复用同一对象来偷懒。

## 外部工具与失败

- MCP/搜索/网页返回均标为 `untrusted`。模型得到的是经 `redact_arguments()` 脱敏、JSON 长度上限为 12,000 字符的 observation，不得把其中内容当成系统指令。
- UI 只显示经过 capability formatter 的来源、数量、文件候选和明确的下一操作，不显示原始 MCP envelope。
- 失败要同时提供给模型 `error_code + retryable + provider/capability`，用户看到针对动作的短说明和稳定错误码。不得把 Python traceback、请求头或 URL 参数交给用户。
- 长任务、下载、写入、审批绝不进入并发分支。只有明确命名的只读 MCP 感知工具，在所有预检均成功后才允许同轮并发。

## 用户界面规则

- 活动时间线表达 `等待输入 / 等待审批 / 正在执行 / 成功 / 失败 / 已取消`，状态来自持久化事件，不能由文案猜测。
- `完成` 必须附着可验证对象：项目、资料、章节、交付物、来源或可点击操作；无法验证时应显示处理中或失败，而非宣称完成。
- 画布、交付物、审批是前端 allow-list 中的结构化 UI action，不执行模型生成的 HTML/JS，不以自然语言“跳转成功”代替按钮。
- 真正的 Trace/Span 与审计详情属于受权运维视图。普通用户页面不展示运行 ID、工具输入输出或模型推理。

## 回归要求

每次修改 Harness、工具适配器或活动时间线，至少验证：

1. 成功工具 observation 在第二次模型调用中可见，而 public event 不含内部字段；
2. 可恢复失败后模型可以继续决策，暂停时模型与 UI 都能获知暂停原因；
3. 两个独立 MCP 只读工具能够并发，写入/审批/下载仍保持串行；
4. 导出、画布与远程资料只以真实链接或 allow-list action 呈现；
5. 桌面与移动浏览器没有溢出、重叠、永久 loading 或错误的终态。
