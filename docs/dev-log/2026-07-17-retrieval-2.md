# Retrieval 2.0 Foundation

- Date: 2026-07-17
- Status: implementation in progress; core retrieval path and development evaluation are complete, release hardening remains.

## Decision Summary

BidPilot keeps PostgreSQL plus pgvector as its only retrieval store. Retrieval
is project-scoped before ranking, uses an immutable embedding profile, combines
dense, FTS, and phrase/trigram candidates through deterministic RRF, and emits
validated citation locators. LangGraph consumes the same contract but does not
own retrieval business state.

The active platform profile is:

```text
openrouter:qwen/qwen3-embedding-8b:1536:bidpilot-lexical-v1
```

Provider credentials remain server environment variables. Browser requests
cannot submit raw vectors, profiles, reranker settings, or provider keys.

## Delivered

- Added profile-aware chunk fields, a safe additive migration, pg_trgm, lexical
  GIN, project/profile, and HNSW indexes.
- Replaced all-zero embedding fallback with typed outcomes. Failed embeddings
  persist no vector and remain sparse-searchable.
- Added shared dense/FTS/trigram repositories, deterministic RRF, optional
  explicit reranking, and citation validation.
- Switched API search to authorize before server-side embedding and return safe
  result/citation fields plus explicit degradation reasons.
- Connected drafting, the LangGraph retriever, and assistant semantic search to
  the same shared service.
- Fixed project isolation in `persist_result`: a same-named section from another
  project can no longer be reused.
- Added RetrievalBench contracts, source-hash verification, ranking/locator/
  scope/degraded-mode metrics, and a CLI for scoring captured runs.

## Important Finding

The first live integration test exposed a CJK FTS recall defect: normalized
bigram queries used strict AND semantics, so a multi-concept question could
return no result despite a relevant chunk. The repository now retries a bounded
OR query over at most 64 normalized terms only when strict FTS has no result.
The fallback remains project-scoped and does not become an unrestricted chunk
fallback.

## Evidence Collected

- Local OpenRouter smoke call returned a nonzero 1536-dimensional embedding
  for the configured model; no credential was printed or persisted.
- PostgreSQL is `17.9` with pgvector `0.8.2`; the configured local version lacks
  `hnsw.iterative_scan`, so the current dense strategy remains exact per
  authorized project rather than relying on filtered ANN behavior.
- API retrieval contracts, schema, repository, embedding, and search tests pass
  on an Alembic-migrated isolated PostgreSQL database.
- Worker indexing, drafting retrieval, graph mapping, reranker, and project
  scope tests pass on the same schema.

## Remaining Before Release

- Implement and record a real four-strategy RetrievalBench run from frozen
  source chunks; do not report hand-authored candidate results as quality.
- Add reindex jobs, stale-count reporting, and an operator runbook for profile
  changes and rollback.
- Add production trace/audit correlation, latency/cost metrics, and release
  gates.
- Run broader API/Worker suites and independent review before deployment.
